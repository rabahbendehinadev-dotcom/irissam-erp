# أولًا: إزالة MOCK_PATIENTS من PatientDetail

يوجد داخل:

`PatientDetail.tsx`

Fallback يستعمل:

`MOCK_PATIENTS`

إذا لم تُرجع الـAPI المريض المطلوب.

هذا ممنوع في Production.

## المطلوب

احذف `MOCK_PATIENTS` من Runtime الخاص بصفحة Patient Detail.

صفحة Patient Detail يجب أن تعتمد فقط على:

* Patient ID الحقيقي من Route.
* API الحقيقية.
* PostgreSQL الحقيقي.
* React Query أو الـService الموجود.

طبق الحالات التالية:

### أثناء تحميل بيانات المريض

اعرض Loading State الموجود في Design System.

### إذا رجعت الـAPI مريضًا حقيقيًا

اعرض Patient Detail بشكل طبيعي.

### إذا رجعت الـAPI 404

اعرض:

`Patient introuvable`

مع:

* زر الرجوع إلى قائمة المرضى.
* عدم عرض أي بيانات وهمية.
* عدم حدوث White Screen.

### إذا رجعت الـAPI 403

اعرض:

`Accès refusé`

### إذا حدث API Error

اعرض:

* Error State.
* زر Réessayer.
* زر الرجوع إلى قائمة المرضى.

### إذا كان Route ID غير صالح

اعرض Not Found State مباشرة.

ممنوع:

* استعمال Mock Patient كـfallback.
* استعمال بيانات ثابتة.
* عرض أول مريض من القائمة بدل المريض المطلوب.
* تحويل الخطأ إلى Empty Patient وهمي.

# ثانيًا: إصلاح Silent Failure داخل Emergencies

حاليًا عند الضغط على:

* Prendre en charge
* Ouvrir

إذا لم يوجد `patient.patientId` حقيقي، الكود ينفذ:

```ts
if (!patient.patientId) return;
```

هذا Silent Failure وغير مقبول في Production.

## المطلوب

إذا لم يوجد `patientId` حقيقي:

* عطّل الزر مسبقًا إذا كان ذلك مناسبًا.
* أو اعرض Error State / Toast واضحًا باستعمال نظام الإشعارات الموجود.
* لا تستعمل `alert()`.
* لا تتجاهل الحدث بصمت.
* لا تنشئ Patient وهميًا.
* لا تستعمل MockRepository.

استعمل رسالة واضحة مثل:

`Impossible d’ouvrir le dossier : aucun patient réel n’est associé à cette visite.`

إذا كان بالإمكان استخراج `patientId` الحقيقي من:

* encounter
* emergency visit
* admission
* patient relation

استعمل العلاقة الموجودة بدل تعطيل الإجراء.

ابحث أولًا في الـBackend والـTypes قبل تعديل السلوك.

# ثالثًا: إغلاق Dev Routes في Production

راجع:

* `/dev/tests`
* `DevTestRunner.tsx`
* أي Route أو Page أو Tool خاص بالتطوير.

في Production:

* لا يجب أن تكون Route مسجلة أصلًا.
* لا يكفي إخفاؤها من Sidebar.
* يجب ربط تسجيلها بشرط:

`import.meta.env.DEV`

أو إزالتها من Production Router.

نفس المبدأ ينطبق على:

* Demo tools
* Test runners
* Seed buttons
* Debug panels
* Development reset actions

# رابعًا: Ambulances

`Ambulances.tsx` مازالت تحتوي على `useMockRepository()` رغم أن Route تقوم بالـredirect.

أريد فصلًا كاملًا عن Production Runtime.

طبق أحد الحلين:

1. لا تستورد `Ambulances.tsx` داخل Production bundle أصلًا.
2. اجعل الاستيراد والـRoute مشروطين بـDevelopment فقط.
3. أو احذف استعمال MockRepository من الصفحة.

لا يكفي أن Route تعمل Redirect إذا كان الملف مازال مستوردًا داخل Production bundle.
