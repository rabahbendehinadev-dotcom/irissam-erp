# Audit شامل لـ Employee Detail وجميع Sidebar Routes

## أولًا: Employee Detail

افحص صفحة Employee Detail وجميع التبويبات الموجودة فيها.

لكل Tab تحقق من:

* هل الـComponent موجود؟
* هل الـAPI موجودة؟
* هل البيانات حقيقية من PostgreSQL؟
* هل React Query أو الـService مربوط بطريقة صحيحة؟
* هل توجد Placeholder أو Coming Soon؟
* هل توجد Tab معطلة أو Disabled؟
* هل توجد White Screen؟
* هل توجد Runtime Errors؟
* هل توجد Console Errors؟
* هل الصلاحيات تعمل؟
* هل Loading State موجود؟
* هل Empty State موجود؟
* هل Error State موجود؟
* هل Retry موجود؟
* هل الصفحة Responsive على Mobile وTablet وDesktop؟

إذا كانت الـAPI موجودة:

* اربط الـTab بها.

إذا كان الـComponent موجودًا لكنه غير مربوط:

* أكمل الربط فقط.

إذا كانت الـFeature غير مبنية أصلًا:

* أخفِ الـTab مؤقتًا.

ممنوع عرض أي Placeholder للمستخدم.

---

## ثانيًا: Sidebar Routes

راجع جميع عناصر الـSidebar واحدًا واحدًا.

لكل عنصر سجل:

* اسم الصفحة.
* Route.
* Component.
* Permission المطلوبة.
* هل Route تعمل؟
* هل الصفحة تُفتح بدون White Screen؟
* هل توجد API حقيقية؟
* هل Loading / Empty / Error / Retry موجودة؟
* هل الصفحة تعمل على Mobile وTablet وDesktop؟
* هل يجب إبقاؤها ظاهرة أو إخفاؤها؟

طبق القواعد التالية:

* 403 → عرض `Accès refusé`.
* 404 → عرض `Page introuvable`.
* لا توجد بيانات → Empty State.
* API Error → Error State مع زر Retry.
* Feature غير جاهزة → إخفاء Menu أو Tab.
* Route مكسورة → إصلاحها أو إخفاؤها.
* ممنوع استعمال PlaceholderPage.
