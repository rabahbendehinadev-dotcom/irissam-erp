ممتاز، هكذا نقدر نقول بلي **الـFoundation راهي مهيأة مليح** ونقدرو نبدأو أول Module حقيقي.

الـStructure اللي دارها Replit مليحة بزاف، خاصة:

* فصل `types` و`services` و`hooks`.
* نظام اللغات الثلاث.
* الصلاحيات.
* Multi-sites.
* Online/Offline foundation.
* Audit.
* API client.
* Shared components.

ما نزيدوش نطلبو Architecture أخرى الآن باش ما نضيعوش الوقت.

المرحلة الجاية تكون:

# Module 1: Gestion des Patients — MPI

وهذا أهم Module، لأنه كل النظام راح يرتبط بالمريض.

انسخ له هذا البرومبت:

```text
الآن ابدأ أول Module حقيقي في نظام IRISSAM HOSPITAL ERP:

MODULE: GESTION DES PATIENTS — MASTER PATIENT INDEX (MPI)

مهم جدًا:

- لا تبدأ أي Module آخر.
- استعمل الـFoundation الموجودة حاليًا.
- لا تغيّر تصميم الـDashboard أو الـLayout.
- لا تهدم أو تعيد تنظيم الـArchitecture الحالية إلا إذا كان هناك خطأ تقني حقيقي، وفي هذه الحالة اشرح المشكلة قبل التعديل.
- يجب أن يدعم Module اللغات الثلاث:
  - Français افتراضيًا
  - العربية مع RTL
  - English
- استعمل حاليًا Mock Data منظمة وقابلة للاستبدال لاحقًا بـ API وقاعدة بيانات حقيقية.
- كل النصوص يجب أن تمر عبر نظام الترجمة الحالي.
- كل العمليات الحساسة يجب أن تمر عبر نظام الصلاحيات والـAudit الموجودين.

==================================================
1. الهدف من Module
==================================================

إنشاء Master Patient Index مركزي يسمح بإنشاء ملف موحد ودائم لكل مريض داخل المستشفى.

يجب أن يستعمل نفس Patient ID في:

- المواعيد
- الاستقبال
- الاستشارات
- الطوارئ
- الاستشفاء
- العمليات
- الإنعاش
- المختبر
- الأشعة
- الصيدلية
- بنك الدم
- الفوترة
- الأرشيف

ممنوع إنشاء نفس المريض مرتين بدون تنبيه واضح.

==================================================
2. صفحة قائمة المرضى
==================================================

أنشئ صفحة احترافية باسم:

Patients

وتحتوي على:

- عنوان الصفحة.
- وصف مختصر.
- زر Ajouter un patient.
- زر Export.
- زر Import لاحقًا، يكون Disabled أو Placeholder.
- عدد المرضى الإجمالي.
- عدد المرضى النشطين.
- عدد الملفات غير المكتملة.
- عدد حالات التكرار المحتملة.

- Archiver

استعمل Archive / Soft Delete فقط.

==================================================
6. Détection des doublons
==================================================

قبل إنشاء المريض، نفذ فحصًا تجريبيًا للتكرار حسب:

- Nom + Prénom + Date de naissance
- Téléphone
- Numéro d’identité
- Numéro de sécurité sociale

إذا وجد احتمال تكرار:

- لا تمنع المستخدم مباشرة.
- اعرض Modal واضحة.
- اعرض الملفات المحتملة.
- اعرض نسبة التشابه.
- أزرار:
  - Ouvrir le patient existant
  - Continuer quand même
  - Annuler

عملية “Continuer quand même” يجب أن تطلب Permission خاصة وتسجل في Audit Log.

==================================================
9. الصلاحيات
==================================================

استعمل usePermission() الحالي.

حضّر Permissions مثل:

- patients.view
- patients.create
- patients.update
- patients.archive
- patients.export
- patients.view_sensitive
- patients.override_duplicate
- patients.view_audit

السلوك:

- إذا ما عندوش view ما يفتحش الصفحة.
- إذا ما عندوش create ما يظهرش زر الإضافة.
- إذا ما عندوش update تكون الحقول Read-only.
- البيانات الحساسة تختفي بدون patients.view_sensitive.
- تجاوز التكرار يحتاج patients.override_duplicate.

==================================================

- فتح ملف مريض

- تعديل مريض
- أرشفة مريض
- تصدير بيانات
- عرض بيانات حساسة
- تجاوز تنبيه التكرار
- تحميل أو إضافة وثيقة

يجب أن يظهر:
- المستخدم
- الوقت
- الإجراء
- Patient ID
- الحقول المعدلة
- القيمة القديمة والجديدة لاحقًا

==================================================

==================================================
16. معايير القبول
==================================================

لا تعتبر Module مكتملًا إلا إذا:

- صفحة القائمة تعمل.
- البحث والفلاتر تعمل على Mock Data.
- Pagination تعمل.
- Form الإضافة يعمل.
- Validation تعمل.
- كشف التكرار يعمل.
- صفحة التفاصيل تعمل.
- Tabs تعمل.
- Timeline تعمل.
- Permissions تتحكم في الواجهة.
- Audit hooks يتم استدعاؤها.
- Multi-site filters تعمل.
- اللغة الفرنسية والعربية والإنجليزية تعمل.
- RTL صحيح.
- الواجهة Responsive.
- لا توجد أخطاء Console.
- لا يتم كسر Dashboard الحالية.
- لا يتم بناء أي Module آخر.

بعد الانتهاء:

1. اعرض Structure الملفات التي أنشأتها.
2. اشرح Components الجديدة.
3. اشرح Permissions المستعملة.
4. اشرح Mock Data.
5. اشرح ما تم تأجيله للـBackend.
6. اعرض قائمة اختبارات يدوية يمكنني القيام بها.
```

هذه المرحلة ما زالت Frontend وMock Data فقط. كي يكملها Replit ونراجعها، بعدها نقرر هل نربط مباشرة الـPatients بقاعدة البيانات والـAPI، أو نبني أولًا نظام Authentication والصلاحيات الحقيقي.
