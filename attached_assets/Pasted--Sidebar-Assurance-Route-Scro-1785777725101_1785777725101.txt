فهمتك. المشكلة في الـSidebar نفسها: كي تضغط على **Assurance** ولا صفحة أخرى، الـRoute تتبدل بصح Scroll تاع القائمة يرجع تلقائيًا للفوق، وبالتالي تضيع البلاصة لي كنت واقف فيها. هذا مزعج خاصة كي تكون القائمة طويلة.

ما تبعثش برومبت Stock دك. صلّح هذي أولًا.

انسخ هذا البرومبت كامل:

```text
المطلوب إصلاح مشكلة حفظ موضع التمرير داخل Sidebar.

المشكلة الحالية:
القائمة الجانبية طويلة، وعندما أنزل إلى قسم مثل:
- Assurance / Tiers Payant
- RH
- Stock
- Biomédical
ثم أضغط على أي صفحة، يتم فتح الصفحة لكن Scroll الخاص بالـSidebar يرجع مباشرة إلى أعلى القائمة.

هذا يجعل التنقل مزعجًا جدًا، خصوصًا في الأقسام الموجودة أسفل القائمة.

المطلوب:

1. حفظ موضع التمرير الخاص بالـSidebar قبل تغيير الصفحة.

2. عند الانتقال إلى Route جديدة:
- لا تعيد Sidebar إلى scrollTop = 0.
- أعد نفس موضع التمرير السابق بعد اكتمال الـNavigation.

3. استعمل تخزين مناسب:
- sessionStorage لحفظ sidebarScrollTop.
- أو state مركزي ثابت لا يعاد إنشاؤه عند كل Route.

4. عند كل Scroll داخل القائمة:
احفظ القيمة الحالية مثل:
sidebarScrollTop = sidebarElement.scrollTop

5. عند Mount أو بعد تغيير Route:
استرجع القيمة المحفوظة:
sidebarElement.scrollTop = savedScrollTop

6. لا تجعل Sidebar يعاد Mount بالكامل عند كل Navigation.
راجع:
- key متغيرة على Sidebar
- Conditional rendering
- Layout component
- ProtectedRoute
- App shell

يجب أن تبقى Sidebar داخل Layout ثابت ومستمر بين الصفحات.

7. العنصر النشط يجب أن يبقى ظاهرًا تلقائيًا:
- إذا Route النشطة خارج الجزء الظاهر، اعمل scrollIntoView({ block: "nearest" })
- لا تحرك القائمة إذا العنصر النشط ظاهر أصلًا.
- لا تعيدها إلى أعلى الصفحة.

8. على Mobile:
- عند الضغط على Route، أغلق Drawer.
- لكن احتفظ بموضع Scroll.
- عند إعادة فتح Drawer، يرجع لنفس القسم السابق.

9. على Desktop:
- Sidebar تبقى ثابتة.
- Scroll position لا يتغير عند تغيير الصفحة.

10. على Refresh الكامل:
يمكن استرجاع آخر موضع من sessionStorage خلال نفس الجلسة.

11. لا تحفظ موضع Scroll الخاص بمحتوى الصفحة داخل نفس المفتاح.
يجب فصل:
- sidebarScrollTop
- pageScrollTop

12. اختبارات القبول:

TEST A:
انزل إلى Assurance واضغط عليها
→ الصفحة تفتح
→ Sidebar تبقى في نفس الموضع.

TEST B:
اضغط على صفحة داخل RH
→ لا ترجع القائمة للفوق.

TEST C:
انتقل بين عدة صفحات أسفل القائمة
→ Scroll ثابت.

TEST D:
Mobile Drawer:
انزل للأسفل → افتح صفحة → افتح Drawer من جديد
→ يرجع لنفس الموضع.

TEST E:
Desktop:
التنقل بين Routes لا يعيد Mount للـSidebar.

TEST F:
العنصر النشط يبقى ظاهرًا بدون قفزة مزعجة.

TEST G:
Refresh داخل نفس الجلسة
→ آخر موضع محفوظ يرجع.

TEST H:
0 Runtime Errors.
0 TypeScript Errors.

بعد الإصلاح أعطني:
- السبب الحقيقي لعودة Scroll إلى الأعلى.
- الملفات المعدلة.
- هل Sidebar كانت تعاد Mount.
- طريقة حفظ واسترجاع scrollTop.
- نتائج TEST A–H.
```

الأغلب السبب واحد من زوج:

* الـSidebar راهي تعاود `mount` مع كل Route.
* أو كاين `scrollIntoView` يستعمل `block: "start"` ويرجعها للفوق.

لازم يصلحها قبل ما نكمل Stock، لأن كل ما تزيد Modules القائمة راح تطول أكثر والمشكل يزيد.
