نفّذ الآن اختبار End-to-End كامل لـ Portail Médecin مع PostgreSQL والـAPI الحقيقية.

ممنوع إضافة Features جديدة.
المطلوب فقط اختبار وربط السيناريوهات السريرية، الصلاحيات، الـScope، الـSignature، والـPWA.

==================================================
1. حسابات الاختبار
==================================================

حضّر:

- Doctor A
- Doctor B
- Medical Director
- User عادي بدون doctor_portal.access
- Patient A مرتبط بـDoctor A
- Patient B مرتبط بـDoctor B
- Patient C منوم تحت مسؤولية Doctor A
- Emergency Patient Assigned لـDoctor A

كل العلاقات تكون من الجداول الحقيقية:
appointments / consultations / admissions / encounters / assignments.

==================================================
2. Auth وAccess
==================================================

TEST A:
Doctor A يسجل الدخول
→ /doctor-portal يفتح.

TEST B:
User بدون doctor_portal.access
→ HTTP 403 + صفحة Access Denied.

TEST C:
Unauthenticated
→ redirect إلى Login بدون Loop.

TEST D:
Logout
→ Session وRefresh Token يبطلان.

==================================================
3. Scope وIDOR
==================================================

TEST E:
Doctor A يفتح Patient A
→ 200.

TEST F:
Doctor A يحاول فتح Patient B غير المرتبط به
→ 403 أو 404.
→ لا Data Leak.

TEST G:
Medical Director حسب صلاحياته
→ يرى المرضى داخل Scope المسموح فقط.

TEST H:
تغيير patientId يدويًا في URL أو Request
→ لا يتجاوز Scope.

==================================================
4. Agenda وPatients du jour
==================================================

TEST I:
Appointment اليوم لـDoctor A
→ يظهر في Agenda وPatients du jour.

TEST J:
Appointment لـDoctor B
→ لا يظهر لـDoctor A.

TEST K:
Marquer arrivé
→ status يتحدث في ERP وDoctor Portal.

TEST L:
Commencer consultation
→ نفس patientId وappointmentId وencounterId الحقيقي.

==================================================
5. Consultation كاملة
==================================================

أنشئ Consultation لـPatient A:

- motif
- histoire maladie
- examen clinique
- constantes
- diagnostic
- plan thérapeutique
- conseils

اختبر:

TEST M:
Enregistrer brouillon
→ draft محفوظ.

TEST N:
Finaliser
→ status finalized.

TEST O:
Signer
→ signedAt + signedBy + contentHash + lockedAt.

TEST P:
تعديل Consultation موقعة
→ ممنوع.

TEST Q:
إنشاء Addendum
→ سجل منفصل مربوط بالConsultation الأصلية.
→ الأصل لا يتغير.

==================================================
6. Lab Order
==================================================

من نفس Encounter:

- إنشاء Lab Order NFS
- priority=STAT
- clinical note

TEST R:
يظهر داخل Laboratory.

TEST S:
encounterId يطابق Encounter الحقيقي.

TEST T:
نتيجة Critical
→ تظهر في Results Inbox وDashboard.

TEST U:
Acknowledge Critical
→ acknowledgedAt + acknowledgedBy.
→ لا تبقى كتنبيه غير مقروء.
→ Audit مسجل.

==================================================
12. Signature Security
==================================================

اختبر:

- contentHash يتغير إذا تغير المحتوى.
- Signed record locked.
- Addendum فقط بعد التوقيع.
- signature مرتبطة بـdoctorId/session/IP/device.
- لا يمكن Doctor B توقيع سجل Doctor A بدون Permission.
- Audit لكل Signature.
