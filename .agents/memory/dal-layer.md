## Critical column name mappings (checked against actual schema)

### admissionsTable
- `type` (not `admissionType`)
- `motif` (not `chiefComplaint`) — **not null**
- `serviceName` / `doctorName` — **not null**
- `admissionDate` (date string) + `admissionTime` (HH:MM text) — no `admittedAt`
- `actualDischargeDate` + `actualDischargeTime` — no `dischargedAt`
- `dischargeNotes` (not `dischargeNote`)
- `admissionNumber` — generated by AdmissionService as `ADM-YYYY-NNNNN`
- `patientMpiId` (not `patientMrn`)

### occupancyBedsTable
- Status enum: `disponible | occupe | reserve | nettoyage | hors_service | maintenance`
- **"libre" does NOT exist — use "disponible"**
- No `freedAt` column — free() clears patientId/encounterId, sets status="disponible"
- No `deletedBy` column

### labOrdersTable
- `test` (not `testName`)
- `urgency` (not `priority`)
- `requestedAt` (not `orderedAt`)
- No `siteId` column
- No `deletedBy` column

### imagingOrdersTable
- `exam` (not `examName`)
- `region` (not `modality`) — not null
- `urgency` (not `priority`)
- `requestedAt`
- No `siteId` column
- No `deletedBy` column

### prescriptionsTable
- Single drug per record: `drug` / `dosage` / `route` / `frequency`
- Status: `prescrit | prepare | delivre | annule` — **"dispensée" does NOT exist, use "delivre"**
- `dispensedById` (not `dispensedBy`)
- No `siteId` column
- No `deletedBy` column

### medicationsTable
- `quantity` (not `stock`)
- `lowStockThreshold` (not `reorderLevel`)

### consultationsTable / appointmentsTable
- No `deletedBy` column (only `deletedAt`)

## sourceModuleEnum values (French!)
`urgences | consultations | hospitalisation | bloc | reanimation | pharmacie | laboratoire | imagerie | admissions | system`
- patients → `"system"`
- lab → `"laboratoire"` (not "laboratory")
- imaging → `"imagerie"` (not "radiology")
- pharmacy → `"pharmacie"` (not "pharmacy")

## Number generation (current — sequential, not atomic)
- MRN: `MRN-YYYY-NNNNN` via `repos.patient.countAll() + 1` — **race condition risk under concurrency (Task #85)**
- Encounter: `ENC-YYYY-NNNNN` via `repos.encounter.countAll() + 1`
- Admission: `ADM-YYYY-NNNNN` via `repos.admission.countAll() + 1`

**Why:** Using COUNT+1 is simple and safe for single-server low-concurrency dev use. Task #85 proposes replacing with PostgreSQL SEQUENCE for production.

## TxContext pattern
```typescript
// In a service:
return db.transaction(async (tx) => {
  const ctx: TxContext = { ...actor, tx };
  const result = await repos.something.create(data, ctx);  // uses tx
  await auditService.log(entry, actor, ctx);               // same tx
  return result;
});
```
